# 实测坑位汇编

每一条都是在真机上踩过、并已定位到根因的。按「现象 → 根因 → 正解」组织。
**判定前通读一遍，能省下大量返工时间。**

---

## A. 测量口径类

### A1. 🚨 Tr/Tf 用了 10%–90% 口径（最贵的坑）

- **现象**：Tr 读到 1584–2034 ns，超 1000 ns 规格，准备去找硬件工程师查上拉电阻。
- **根因**：I²C 规范（NXP UM10204）的 Tr/Tf 定义基准是 **30%–70%**。10%–90% 会把波形平坦的尾部算进来，虚高 2–3 倍。
- **正解**：一律用 30%–70%。改用后同一批数据是 585–689 ns，全部合格。
- **教训**：Tr 偏大 2–3 倍且波形呈 RC 曲线时，**先查口径**，不要查硬件、不要问工程师。
- **另注**：仪器测量面板的「阈值类型」若显示 `30% / 50%`，也**不是**规范口径 —— 面板 Tr 读数不能直接用。

### A2. `i2c_decode.py` 内置的 Tr/Tf 是 10%–90%

- **现象**：解码器输出的 `scl_transition.tr` 是 `null`，`tf` 是 142 ns，与实际不符。
- **根因**：该解码器的 `trans_times` 用 10%–90%，在慢速 RC 沿上找不到 90% 上穿点，于是返回 null。
- **正解**：**Tr/Tf 一律另用 `tr_measure.py` 复算**（默认 30%–70%）。解码器的其余 10 个时序量可以照用。

## B. 取数类

### B1. `:WAVeform:POINts? MAXimum` 给的点数偏小

- **现象**：取回的波形「看着不准」，游标对不上参考图。
- **根因**：`?MAX` 返回的是**屏幕当前显示点数的上限**（实测 2173 点 = 46 ns/点），不是内存能给的最高分辨率。
- **正解**：显式 `:WAVeform:POINts 100000` → 1 ns/点，精细 46 倍。

### B2. DELay 超出内存时 `POINts?` = 0，硬等会卡十几分钟

- **现象**：脚本挂住不动，像死机。
- **根因**：窗口被推出已采集内存后 `:WAVeform:POINts?` 返回 `0`，而 `:WAVeform:XORigin?` 会卡约 18 秒超时。
- **正解**：取数前先查 `POINts?`，`<= 0` 立刻抛错退出，不要硬等数据块。

### B3. 数值参数拼成双重指数导致设置静默失效

- **现象**：`:TIMebase:POSition` 设了没反应，但同一脚本里游标位置却对了。
- **根因**：`"%.10gE-6" % 40e-6` → `"4e-05E-6"`，触发 `-131 Invalid suffix`。
  位置命令不生效，而 `:MARKer:X1Position` 恰好容错解析了。
- **正解**：一律 `repr(float(x))` 传纯秒数字。

### B4. 拼接数据步长不统一 → 索引偏一倍 → 假 FAIL

- **现象**：凭空多出 15 个 START / 13 个 STOP，`tSU;STA = 0.1666 µs` 判 FAIL。
- **根因**：拼接后第一窗口 6 ns/点、其余 12 ns/点。代码用首段步长当全局步长，索引偏一倍。
- **正解**：边沿用逐点步长插值；电平判定用时间轴二分定位。

## C. 仪器状态类

### C1. 冻结记录上改采集设置是无效操作

- **现象**：`:CHANnel:N:BWLimit OFF` 之后 Tr 没变，以为「带宽限制无关紧要」。
- **根因**：仪器拿**已存储的采样点**重算测量，不会回溯重采。冻结数据上改任何采集类设置都无效。
- **正解**：要验证带宽限制的影响必须**重新采集**。
- **推论**：看到「关掉 XX 后数值不变」时，先问「数据是冻结的还是新采的」。

### C2. 面板「带宽限制 20MHz」按钮高亮 ≠ 生效

- **现象**：截图里按钮是绿色高亮，据此判定带宽受限 → 误判。
- **根因**：那只是该按钮的「可点击」指示，不代表限制已开启。
- **正解**：以 SCPI 为准 —— `:CHANnel<n>:BWLimit?` = `0`（关闭）/ `1`（开启）；
  `:CHANnel<n>:BANDwidth?` = `+1.00000000E+009`（1 GHz，全带宽）。

### C3. `:CHANnel<n>:PROBe` 在部分 WinCE 固件上改不动

- **现象**：`:CHANnel2:PROBe 1.0` / `:PROBe:VALue 1.0` / `:PROBe:ATTenuation 1.0` 全部不生效，`PROBe?` 始终回 `+10.000000E+00`。
- **正解**：只能在**示波器面板上操作**（通道菜单 → 探头）。`PROBe:SKEW?` / `PROBe:STYPe?` 可读。

### C4. 修复前的仪器状态要还原

- **清单**：`:TIMebase:SCALe` / `:TIMebase:POSition` 回原值、`:MARKer:MODE OFF`、
  循环抽干错误队列到 `+0,"No error"`。
- 理由：用户可能正在用这台机器做别的测试，改了不还原会污染别人的现场。

## D. 现场纪律类

### D1. 别用 `:RUN` 覆盖用户冻结的波形

- **现象**：用户说「已经截好图了」，一发 `:RUN` 那屏波形就被新采集覆盖，若总线已停则只剩平线，**不可恢复**。
- **正解**：只看当前记录时**不要发 `:RUN` / `:SINGle`**。先判断是否必须重新采集。

### D2. 开工前先确认输入端真有信号

- **正解**：4 通道各取 3000 点看 `y[min,max]`。全 ~0 V 平线 → 探头脱落 / DUT 掉电。
  此时任何「测量」都是噪声，**不要继续、更不要凭噪声出数**。
  空闲 I²C 总线应是 ~3.3 V 高电平，读到 0 V 即异常。

### D3. 长记录 + 全噪声会让解码器段错误

- **现象**：`analyze()` 在 25k+ 伪边沿的记录上崩溃。
- **正解**：取数后先做电平/信号自检，确认有真实 I²C 波形再送解码。

### D4. 多窗口拼接的边界残段会污染统计

- **正解**：默认跳过记录开头 1%（触发点在记录中，开头常含半截沿，会被误算成 ms 级）。
  可用 `--t-min-us` 显式指定只统计晚于某时刻的沿。

## E. 报告回填类

### E1. 🚨 含 OLE 嵌入对象的 xlsx 不能用编辑器保存

| 手段 | 后果（实测） |
|---|---|
| 本地 Office 编辑器 open→写→save | **OLE 包全灭**：embeddings 2→0，条目 158→164，体积 4 151 834→3 924 098 B |
| `openpyxl.load_workbook` 后 `save` | 同样丢绘图/媒体：3.94 MB→3.53 MB，掉 410 KB |
| ✅ zip/XML 层逐条复制改写 | OLE 一字节不动，条目数、embeddings 完全不变 |

- **正解**：文件里只要有 `xl/embeddings/`，就改用 `xlsx_cellpatch.py`。

### E2. 合并单元格：值必须写在合并块左上格

否则 Excel 显示空白。常见形态是「每 2 物理列合并成 1 显示列」（E:F、G:H …）。

### E3. 用正则抠格时自闭合标签会错位

- **现象**：从 sheet XML 解析单元格，得出「值右移了一列」的结论，白查半小时。
- **根因**：正则没处理 `<c .../>` 自闭合形态，把相邻格揉在一起。
- **正解**：`re.findall(r'<c r="([A-Z]+\d+)"([^>]*?)(?:/>|>(.*?)</c>)', xml, re.S)`

### E4. 编辑器的 sheet_id 是每个文件独立分配的

- **现象**：同一报告的两个版本，用一个文件读到的 sheet_id 去读另一个，报 `sheet not found`。
- **正解**：换文件先取当前 sheet_id。

### E5. 编辑器打开过文件就占句柄

- **现象**：`os.replace` / `rename` 抛 `PermissionError [WinError 5] 拒绝访问`。
- **根因**：原子替换需要独占句柄。
- **正解**：`shutil.copy2` 覆盖**能成功**；收尾先 `close_file`，
  且池状态可能缓存不刷新（报 "no editor open" 但池里还列着）。

### E6. 回读拿到的是单元格显示值

- **现象**：写 5.4053、回读 5.41，误报「不一致」。
- **根因**：单元格有 2 位小数格式。
- **正解**：比较时对数字做「按回读精度舍入后」的比对。
  **解析回读串必须用 `csv` 模块** —— `split(",")` 会被 Notes 里的逗号打断。

### E7. 长文本 Notes 用 `t="inlineStr"`

避免动 `sharedStrings.xml`。文本里的 `<` `&` 要转义（或改用中文表述如「不大于」代替 `<=`）。

## F. 环境类

### F1. Git-Bash 的 `/tmp` ≠ Windows Python 的 `/tmp`

Bash 里 `cat /tmp/x.py` 读得到，Python 里 `open("/tmp/x.png","wb")` 会去 `C:\tmp\` 报 FileNotFoundError。
→ **脚本内一律写绝对路径**，只有命令行参数能用 `/d/...`。

### F2. 不用 heredoc 写含引号/中文的 Python

转义会被吃掉导致 SyntaxError。落盘再跑。

### F3. 必须 `python -u`

进程被超时杀掉时缓冲的 stdout 会整段丢失，看起来像「什么都没输出」。

### F4. 文件名含 `;` 在 shell/bat 里会被当命令分隔符

→ 走 Python `shutil.copy2`，不要在 shell 里直接拼路径。

### F5. 部分环境的 PowerShell 安全策略拦 `Add-Type` / `New-Object -ComObject`

→ 需要 COM 能力时改用 Python（pywin32 / ctypes）。
